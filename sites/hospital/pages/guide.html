How it works

Follow one blood test from Hospital B's lab to a doctor at Hospital A, and then to the patient. About 5 minutes.

Two separate websites, on purpose

Each hospital is its own site with its own data. Open both in two tabs:

Hospital B sends the results → Hospital A receives them

Only the result file you download travels between them. Hospital B's test list, its approvals and any AI key never leave Hospital B's site.

  1. 1

    List the lab's tests

    Lab / IT · Hospital B
    In a real hospital
    The analyst exports the test list from the lab system (code, name, unit, normal range) or collects sample result messages, then loads it into a mapping tool such as Regenstrief's RELMA.
    Here
    On Hospital B's Lab & IT page, the sample list is already loaded. You can also upload a CSV or add a test by hand.
    Open Hospital B · Lab & IT →
  2. 2

    Match each test to a LOINC code

    Lab / IT · Hospital B
    In a real hospital
    The analyst searches LOINC and picks the right code for each test, by hand, often starting with the most-used tests. It is slow, which is why AI helpers are now being built.
    Here
    Each test shows a suggested code. Press Approve if it is the same test, Change to pick another, or Skip. Optional: connect a Meta key and press Suggest with AI. Approve at least GLU-F, CREA and K.
    Approve codes at Hospital B →
  3. 3

    Send a patient's results

    Hospital B's systems
    In a real hospital
    It's automatic. The interface engine (the software between the lab system and other hospitals) sends an HL7 result message. Each result line holds the lab's own code and the approved LOINC code side by side (field OBX-3).
    Here
    On Hospital B's Send results page, fill in a pretend patient's results (or use the sample), see the message, and download the file.
    Open Hospital B · Send results →
  4. 4

    Receive and line up

    Doctor / nurse · Hospital A
    In a real hospital
    Hospital A's system reads the LOINC codes. Results without one arrive as unmatched text the doctor has to work out.
    Here
    On Hospital A's Doctors & nurses page, press Open a received file. Approved tests line up with A's own earlier results, converted to A's units. Tests you didn't approve land in "do not compare".
    Open Hospital A · Doctors & nurses →
  5. 5

    The patient reads their report

    Patient
    In a real hospital
    Patients see their results in a patient app, often with the lab's short names.
    Here
    The Patients page shows each code as a plain name, the lab's range, and what the test is (from MedlinePlus). No AI here.
    Open the patient view →
What is real and what is pretend?
  • Real: LOINC codes and names, the HL7 v2 message layout, unit conversion factors (Labcorp), test explanations (MedlinePlus), and the way labs map codes (RELMA-style review by a person).
  • Pretend: both hospitals, every patient and every number.
  • Simplified: the file download and upload stands in for the interface engine and network link between hospitals.

Sources: LOINC mapping FAQ · RELMA overview · AHRQ on LOINC · CDPH lab reporting HL7 guide (OBX-3)
